DataReel System Monitor

DRSM watches the connectivity and health of your servers, workstations and cloud hosts. Checks are small BASH plugins, alerts go out by email and text, and a fast Web dashboard shows the state of every host at a glance.

What DRSM does

Connectivity

Ping, HTTP, HTTPS (with certificate checks) and FTP probes from the monitor host. Cloud hosts that block ping are checked with an SSH login.

System health

CPU (including cloud steal time), load, memory and swap, disk space and inodes, software and hardware RAID, network errors, and logged in users.

Plugins

Every check is a folder with a manifest and one BASH script. Add your own check without touching a core script.

Situational awareness

Overview, heat map, hosts and connectivity pages, on desktop, phone and NOC wall screen, in light or dark.

Alerts

Email and email to text alerts, throttled to one per problem every 4 hours, with the business impact in each message.

Databases

MySQL and Postgres backup, statistics and maintenance scripts, with stored credentials for unattended runs.

How it works

DRSM runs from cron on one monitor host. bin/drsm_run.sh reads one file per host from etc/hosts, probes each host from the outside, and runs the host's plugins on it in a single SSH session. It writes plain text reports and a status.json per host. The Web dashboard reads those files, and errors go out as email and text alerts.

Nothing needs to be installed on a monitored host except a user account with keyed SSH access. The plugins are copied over on the first run and only again when they change.

Deployment setups

DRSM runs anywhere there is BASH and SSH. Two setups are in use today and are described step by step in Deployment setups:

Production cluster

DRSM on a 3 node cluster, checks run once from the active node, dashboard served by the cluster.

Workstation and hosted dashboard

DRSM on a workstation, with the dashboard on the datareel.com website (HostGator) for OSA and OCA.
