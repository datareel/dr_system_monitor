DataReel System Monitor

DRSM watches the connectivity and health of your servers, workstations and cloud hosts. Checks are small BASH plugins, alerts go out by email and text, and a fast Web dashboard shows the state of every host at a glance.

What DRSM does

Connectivity

Ping, HTTP, HTTPS (with certificate checks) and FTP probes from the monitor host. Cloud hosts that block ping are checked with an SSH login.

System health

CPU (including cloud steal time), load, memory and swap, disk space and inodes, software and hardware RAID, network errors, and logged in users.

Plugins

Every check is a folder with a manifest and one BASH script. Add your own check without touching a core script.

Situational awareness

Overview, heat map, hosts and connectivity pages, on desktop, phone and NOC wall screen, in light or dark.

Alerts

Email and email to text alerts, throttled to one per problem every 4 hours, with the business impact in each message.

Organizations and sites

Customers and offices on one dashboard: an Organizations page with a heat map per site, a site picker, per site alerts, several monitor hosts feeding one dashboard, and logins limited to their own sites.

Tiers and site links

DEV, QA and OPS tiers with a tier filter and per tier alert addresses, and a Site links menu with nested submenus for each site's own tools and runbooks.

Databases

MySQL and Postgres backup, statistics and maintenance scripts, with stored credentials for unattended runs.

How it works

DRSM runs from cron on one monitor host. bin/drsm_run.sh reads one file per host from etc/hosts, probes each host from the outside, and runs the host's plugins on it in a single SSH session. It writes plain text reports and a status.json per host. The Web dashboard reads those files, and errors go out as email and text alerts.

Clientless or agent

  • Linux, clientless: nothing is installed on the host except a user account with keyed SSH access. The plugins are copied over on the first run and only again when they change. For hosts the monitor host can reach over SSH.
  • Linux, agent: the DataReel Reporting Agent for Linux (RHEL 8, 9 and 10) sends a signed report over HTTPS every 15 minutes, with optional vulnerability scans. For hosts DRSM cannot reach, such as cloud servers behind NAT.
  • Windows, agent only: the DataReel Reporting Agent for Windows sends its report over HTTPS, a CIFS share or SCP. DRSM never connects to a Windows host.

Agent hosts only make outgoing connections, so the monitor host can run anywhere, even on the web server that receives the reports. See Clientless and agent monitoring.

What's new

DRSM had a full code review and several feature updates in October 2026. See What's new for the details.

Code review and modernization

More than 30 monitoring and security fixes, RHEL 10, Debian, Ubuntu, PHP 8 and cloud server support.

Plugin module system

drsm_run.sh, the plugin contract, host files, and a migration tool from systems.dat.

Dashboard redesign

Situational awareness Overview, heat map with status icons, host reports with gauges, and a Web only package for shared hosting.

Organizations and sites

Deployment setups

DRSM runs anywhere there is BASH and SSH. Two setups are in use today and are described step by step in Deployment setups:

Production cluster

DRSM on a 3 node cluster, checks run once from the active node, dashboard served by the cluster.

Workstation and hosted dashboard

DRSM on a workstation, with the dashboard on the datareel.com website (HostGator) for OSA and OCA.

Maintaining DRSM with AI assistants

DRSM ships guides for GitHub Copilot, Gemini, Claude and other AI coding assistants, so an admin can ask one to add a host, write a plugin or change the dashboard and get changes that follow the DRSM rules. The source has AGENTS.md, read by most assistants, with .github/copilot-instructions.md, GEMINI.md and CLAUDE.md pointing to it, and llms.txt as an index.

AGENTS.md

Layout, report format, coding rules, tests and releases.

Maintain a site

Hosts, plugin settings, sites, links, alerts, cron, upgrades, and why a host is red.

Write a plugin

The manifest, the script, the helpers and the rules for a new check.

Change the dashboard

Settings, reports from your own scripts, menu items, styles and PHP page rules.

All of them in one file to paste into a chat: llms-full.txt.
