What's new

DRSM had a full code review and three feature updates in October 2026. All of it was written by Claude Code at the request of the project owner. The complete list of changes is in CHANGELOG.md.

  • Dashboard login New

    October 24, 2026 · PR #7

    An optional login for access from outside your internal networks, while the internal network gets straight in. Off by default.

  • HTML documentation

    October 24, 2026

    These pages: a browsable version of README.txt, PLUGINS.md and CHANGELOG.md, with screenshots and the deployment setups. Installed to ~/drsm/docs.

  • Heat map status icons

    October 24, 2026 · PR #5

    The heat map shows a status icon in each cell (check, triangle, cross, question mark) instead of a solid colored box, so states read without relying on color alone, and problem cells are shaded.

  • Web only package and live demo

    October 23, 2026 · PR #4

    utils/make_web_demo.sh builds the dashboard for a PHP only host such as HostGator, unpacked into any folder. With -s it adds sample reports for a public demo, now live at datareel.com/drsm/dashboard.

  • Dashboard redesign

    October 23, 2026 · PR #3

    • Overview page for situational awareness: status banner, counters, Needs attention list, group checks, host matrix and host cards with search and filters.
    • Heat map of hosts against plugin checks, or against CPU, memory, disk, load and swap use.
    • Host reports with resource gauges and a collapsible panel per plugin, problems first.
    • Sortable Hosts table and a Connectivity page for every host group.
    • Light and dark themes, auto refresh with pause, wall display mode, stale host detection, and layouts for phones, tablets and desktops.
    • Branding through $SITEtitle and site/custom.css. Pages tested with PHP 7.2 and 8.3 in CI.

    See Web dashboard. The pages now need PHP 7.2 or higher, and a custom page_header.php must print drsm_head_assets().

  • Plugin module system, phase 1

    October 23, 2026 · PR #2

    • bin/drsm_run.sh replaces the per host loops in system_check.sh and system_report.sh, writes the same reports, and adds a status.json per host.
    • The plugin contract: a folder with plugin.conf and check.sh or probe.sh, settings as DRSM_<KEY>, Nagios exit codes, and METRIC lines.
    • All eleven existing checks ported as plugins with the same messages and levels.
    • Collectors for the monitor host and for Linux over SSH, one session per host.
    • Host files in etc/hosts, a migration tool from systems.dat, and utils/new_plugin.sh.

    Nothing was removed; the old scripts keep working. See Plugins.

  • Release 1.30: code review and modernization

    October 23, 2026 · PR #1

    A full review to run DRSM on RHEL, Rocky and Alma 8 to 10, Fedora, Debian 11+, Ubuntu 20.04+, PHP 7.2 to 8, and cloud servers. The fixes that mattered most:

    • Checks that never fired. The HTTP check always passed, even with the server down. system_report.sh never noticed a failed SSH login and reused the last run's results when a check failed. The network retry compared a value with itself. Load warnings were reported as errors and the fixed 35/50 levels never fired on small VMs.
    • Wrong numbers. CPU use was the average since boot, not current use, and broke on hosts with 10 or more CPUs. Free memory ignored the kernel's MemAvailable. Disk checks missed btrfs and anything not in /etc/fstab.
    • Security. Report text was run through PHP include(), so remote output could run code on the Web server. Host names accepted ../. A stale lock could kill unrelated processes. MySQL passwords showed in ps. SSH now refuses changed host keys.
    • Modern platforms. Runs under dash on Debian cron, no bc needed, curl instead of wget (RHEL 10), PHP 8 fixes, MySQL 8 support, mdadm RAID checks, Intel and AMD CPU temperatures, and cloud hosts that block ping.
