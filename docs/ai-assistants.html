AI assistants

DRSM ships guide files that let an AI agent, such as Gemini CLI, Claude Code or GitHub Copilot, assist your own admins and developers to install, upgrade, maintain, change and troubleshoot DRSM, one step at a time. The agent assists people; it never acts on its own.

Before you use AI assistance

Before you use any AI assistance, review all of your agency's or company's AI usage policies, and get formal written approval from your management team in the form of a business use case and justification. AI desktops and command line tools may be used with DRSM and these guides only in strict compliance with those policies and that approval.

Use only approved enterprise AI models. An AI agent working on DRSM may process potentially sensitive data, such as host names, addresses, configuration files, reports, logs and command output. Use only your agency's or company's enterprise AI models that have built-in safeguards against disclosing information and that guarantee your internal information will not be used to train public models.

Warning: public or free AI tools, open source AI models and self-built AI models may expose your information to public learning models or to other parties, depending on how the model is hosted, configured and licensed; use them only after a comprehensive review of what information might be exposed and what the potential risks are. The entire risk of AI-assisted use rests with you; see the terms of use.

No endorsement. Any mention of a specific AI tool, model or product on this page or in the guide files, such as Gemini, Gemini CLI, Claude Code or GitHub Copilot, is a reference only. It is not an endorsement or a recommendation to use that product. Product names are trademarks of their respective owners.

The guide files and utils/drsm_preflight.sh send nothing to DataReel. Anything you give an AI tool goes to that tool's provider and is governed by the provider's terms and privacy policy and by your AI usage policies (see the privacy policy). Never give an AI tool passwords, SSH keys, the dashboard login settings or agent keys.

Human in the loop, never autonomous

  • Advisory mode is the default. The agent explains each step and prints the exact command and the host it is for; your admin runs it and pastes the output back.
  • Where your policy lets the agent run tools, each command still needs its own approval. Never use auto-approve modes: no Gemini CLI --yolo or auto-accept, no Claude Code permission bypass, no auto-run in other agents.
  • Nothing runs unattended, in batches or in loops over hosts. Scripts that change files show a dry run first and need --apply.
  • The guide files contain no code that runs by itself, and the pre-flight check is a read-only script your admins run, so everything works with advisory-only AI policies.

The guide files

FileRead by
AGENTS.mdThe main guide: AI usage policy, rules for agents, layout, coding rules, tests, support. Read directly by Claude Code, GitHub Copilot, Codex and other agents
GEMINI.mdGemini CLI and Gemini Code Assist; imports AGENTS.md

.github/copilot-instructions.mdGitHub Copilot; points to AGENTS.md

llms.txt, llms-full.txtThe list of guides, and all of them in one file to paste into an approved chat

They are in the top folder of the DRSM source. For an install, open the source folder, or copy AGENTS.md, GEMINI.md, CLAUDE.md and docs/ai/ to the folder you open (for example the DRSM account's home), so the agent finds them.

The read-only check

Start every install, upgrade and support case with the pre-flight check, run as the DRSM user, and give the output to the agent. It changes nothing, contacts no host and prints counts instead of host names or alert addresses:

$ ~/drsm/utils/drsm_preflight.sh
$ ~/drsm/utils/drsm_preflight.sh --source=$HOME/git/dr_system_monitor-<new>   # before an upgrade

GitHub Copilot in VS Code

  1. Install VS Code with the Remote - SSH and GitHub Copilot extensions, signed in with your organization's approved Copilot account.
  2. Connect to the monitor host as the DRSM user (Remote-SSH: Connect to Host) and open the DRSM source or home folder.
  3. Copilot Chat reads .github/copilot-instructions.md and AGENTS.md from the open folder. Leave terminal auto-approve off, so every command waits for you.

Gemini CLI or Gemini Code Assist

$ cd ~/git/dr_system_monitor
$ gemini              # reads GEMINI.md, which imports AGENTS.md; no --yolo

Gemini Code Assist in VS Code reads GEMINI.md from the open folder too.

Claude Code

$ cd ~/git/dr_system_monitor
$ claude              # reads CLAUDE.md, which imports AGENTS.md; no permission bypass

A chat with no access to the host

Paste llms-full.txt into an approved chat, describe the change, copy back only the code and test it on the host. Remove host names, addresses and other site data first when your policy requires it.

Good requests

  • "Help me install DRSM on this monitor host. Here is the drsm_preflight.sh output."
  • "Plan the upgrade from 1.32 to the new release; here is the pre-flight with --source."
  • "Add web2 as a production Linux host with a 90% disk warning, then show me the command to run it once without alerts."
  • "Write a plugin in plugins/local that warns when /var/spool/app has more than 500 files, with a test."
  • "web3 is Stale since yesterday. Tell me which logs and cron lines to check."

Review the result

  • Read every command and change before it runs or is saved. Check a dry run before --apply.
  • Run the tests in the source (tests/*.sh) after a code change, and drsm_run.sh -n -H <host> -v after a host change.
  • Configuration belongs in host, site and config files, not in the DRSM code, so an upgrade keeps it.

AI-assisted support

Start with your AI agent and docs/ai/support.md: where to look, common problems, and the cases where the agent must stop and hand over to your admins. The agent assists your admins; it does not replace them or DataReel. If you are still stuck, contact DataReel (topic "Application support" or "Bug report") and attach the drsm_preflight.sh output and the support summary the agent writes, without passwords, keys or other secrets. Please allow 3 to 5 business days for a reply.
